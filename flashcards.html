Quelles sources de module acceptent version ? Comment figer un module Git ?Which module sources accept version? How do I pin a Git module?

Top 6raté 3×missed 3×

Seulement les registres, public et privé. Ailleurs, version provoque une erreur. Un module Git se fige avec ?ref= dans l'URL.

Registries only, public and private. Anywhere else, version is an error. A Git module is pinned with ?ref= in the URL.

module "local_one" {
  source = "./modules/network"                  # local: no version, it's my code
}

module "public_one" {
  source  = "terraform-aws-modules/vpc/aws"     # NAMESPACE/NAME/PROVIDER
  version = "~> 5.0"
}

module "private_one" {
  source  = "app.terraform.io/acme/net/azurerm" # HOST/ORG/NAME/PROVIDER
  version = "~> 1.0"
}

module "git_one" {
  source = "git::https://github.com/acme/infra.git//modules/net?ref=v1.2.0"
}

Changer source ou ref → relancer terraform init.version → registry only. A private registry shows the host first (4 segments instead of 3). Changing source or ref → run terraform init again.

Run tasks ou run triggers : quelle différence ?Run tasks vs run triggers: what's the difference?

Top 6raté 2×missed 2×
  • Run task : brancher un outil externe dans un run (scan de sécurité, estimation de coût).
  • Run trigger : quand ce workspace applique avec succès, un run est mis en file dans un autre workspace.
  • Les politiques (Sentinel / OPA) sont vérifiées après le plan, avant l'apply. Niveaux : advisory (avertit), soft-mandatory (contournable par un utilisateur autorisé), hard-mandatory (doit passer).
  • Run task: plug an external tool into a run (security scan, cost estimate).
  • Run trigger: when this workspace applies successfully, a run is queued in another workspace.
  • Policies (Sentinel / OPA) run after the plan, before the apply. Levels: advisory (warns), soft-mandatory (authorised users can override), hard-mandatory (must pass).
# run trigger: between workspaces
network-prod ── apply OK ──▶ run trigger ──▶ app-prod: new run queued

# inside one run
plan ──▶ run task (security scanner) ──▶ policies (Sentinel/OPA) ──▶ apply

  • Execution modes: Remote, Local (plan/apply on my machine, state in HCP), Agent. "Speculative" is not a mode.

raté 2×missed 2×

Both go with terraform init after changing the backend block.

Quelles conditions personnalisées arrêtent le run ?Which custom conditions stop the run?

raté 1×missed 1×

validation, precondition, postcondition → erreur, le run s'arrête. Le bloc check → avertissement seulement, le run continue.

validation, precondition, postcondition → error, the run stops. A check block → warning only, the run continues.

variable "env" {
  type = string
  validation {                                  # error → run stops
    condition     = contains(["dev", "prod"], var.env)
    error_message = "env must be dev or prod."
  }
}

resource "local_file" "conf" {
  filename = "app.conf"
  content  = "env=${var.env}"
  lifecycle {
    postcondition {                             # error → run stops
      condition     = self.content != ""
      error_message = "Empty config."
    }
  }
}

check "conf_present" {                          # WARNING only → run continues
  assert {
    condition     = fileexists("app.conf")
    error_message = "app.conf is missing."
  }
}
Image à retenirMemory hookSeul check chuchote. Et Terraform ne revient jamais en arrière : ce qu'un apply interrompu a créé reste dans le state.Only check whispers. And Terraform never rolls back: whatever an interrupted apply created stays in the state.

TF_LOG et TF_LOG_PATH : qui fait quoi ?TF_LOG and TF_LOG_PATH: who does what?

raté 2×missed 2×

Du plus bavard au moins bavard : TRACE → DEBUG → INFO → WARN → ERROR.

Most to least verbose: TRACE → DEBUG → INFO → WARN → ERROR.

TF_LOG=DEBUG terraform plan                      # logs on stderr (the terminal)
TF_LOG=TRACE TF_LOG_PATH=tf.log terraform plan   # logs written to tf.log
TF_LOG_PATH=tf.log terraform plan                # NOTHING is written
TF_LOG=JSON terraform plan                       # a format (TRACE in JSON), not a level
